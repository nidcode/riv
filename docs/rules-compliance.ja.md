## ルール / API 利用規約で禁止されていること（riv は遵守しています）

| ルール | riv の遵守方法 |
|---|---|
| 他の参加者や AWS スタッフに害を与えない | 読み書きするのはあなた自身のスケジュールだけです。他人のデータのスクレイピングや、カタログの大量再配布は行いません。 |
| 知的財産を侵害しない | サンプル / mock データはすべて合成データで、コード内で生成されます（`src/mock/catalog.rs`）。実際のカタログはコミットも配布もされず、ユーザーのローカルデータベースにのみ存在します。 |
| オリジナル作品であること | コードはこのプロジェクトのために書かれたものです。先行プロジェクト（reinvent26-planner、re:Plan 2026、reinvent-scout、reinvent2026-mcp）は記事でクレジットしており、コピーはしていません。 |
| API クォータ | オペレーションごとの分あたりクォータはクライアント側で追跡します（`src/api/quota.rs`）。バッチは残りクォータに合わせて縮小し、`429` では `Retry-After` の間待機します。固定スリープでの連打は行いません。実 API に対するテストは読み取り専用で、オプトイン方式です（`RIV_REAL_API=1`）。 |
| トークンの扱い | アクセストークンは API ベース（`api.awsevents.com`。mock の場合のみ上書き可能）にしか送信しません。トークンは、ログ、URL、エラー、コミット、構造化ログのいずれにも出力しません（`Credentials` はマスキングする `Debug` を持ちます）。0600 のファイルに保存し、リフレッシュトークンはローテーションされたら置き換え、`riv logout` は失効させてから削除します。 |
| 401 の扱い | 1 回だけリフレッシュして 1 回だけ再試行し、その後は停止します（ループしません）。 |
| 登録が必要 | このツールは参加者としてサインインし、その登録に依拠します。認証を回避しようとはしません。 |

## riv が自ら行わないと決めていること（自主規制）

- **ポーリングによる自動予約を行わない。** 空席を監視する・再試行するループはありません。書き込みは、承認された plan に対して 1 回だけ行われます。
- **承認された plan なしで apply しない。** `riv apply` には `--plan`（または plan から作成された run の `--resume`）が必要です。plan は 30 分で期限切れとなり、spec、観測したスケジュール、アカウントに紐づきます。
- **riv が作成していない予約に干渉しない。** それらは `unmanaged (untouched)` として一覧表示されます。spec から行を削除してもキャンセルされず、unmanaged な予約に対する `want: none` は警告を出すだけです。
- **結果不明の後に盲目的に再送しない。** まず `GetSchedule` で突き合わせます。
- **実 API への書き込みベンチマークを繰り返さない。** bench コマンドは読み取りのみを行うか、mock に対して実行します。
- **prep ノートのために動画のトランスクリプトを取得しない。** 引用は短く、出典リンクを付けます。
- **ホスト型のコンポーネントを持たない。** すべて参加者のマシン上で動作します。
